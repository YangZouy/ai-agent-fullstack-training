九、三个实际⼯程问题
问题⼀：恢复时，审批节点从头再执⾏
•
现象：resume后节点函数从头重跑，不是从 interrupt() ⾏继续
•
原因：LangGraph只保存State和检查点，不保存Python调⽤栈
•
⻛险： interrupt() 前的副作⽤（部署、写⽂件、扣款）可能重复执⾏
•
避免：副作⽤放到审批通过后的独⽴节点；外部请求⽤幂等键
•
提醒：恢复会重跑代码，不会撤销已发⽣的外部操作
问题⼆：复⽤旧checkpoint污染测试
•
现象：单独跑通过，重复跑或并⾏跑状态异常（如 canary_cursor 停在1，预期3）
•
原因：同⼀SQLite+同⼀ thread_id ，读到上⼀轮旧checkpoint
•
避免：每会话⽤⼲净checkpointDB；不同⽤例⽤不同 thread_id ；fixture清理
•
提醒：测试不仅要准备输⼊，也要准备⼲净的持久化状态
问题三：异步节点⾥阻塞I/O卡住事件循环
•
现象：命令⾏正常， langgraph dev 中 finalize 写报告被blockbuster拦截
•
原因： async def 中执⾏同步⽂件I/O（ os.mkdir 、 Path.write_text ），阻塞事件循
环
•
避免：短同步操作写成普通 def （线程池执⾏）；必须异步则改⽤异步I/O；多环境验证
•
提醒： async def ≠内部操作异步，逐项检查I/O是否阻塞
本章⼩结：把业务流程变成可执⾏、可恢复的图
